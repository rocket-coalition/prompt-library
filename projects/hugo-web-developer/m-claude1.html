Static Engineering for
People Who Build Things

I treat Hugo less like a templating engine and more like a full application platform. By combining HTMX, Alpine.js, and highly optimized front-end patterns, I achieve features normally requiring dynamic backends—all with minimal hosting complexity and sub-millisecond template resolution.

Hypermedia-driven UI updates that make Hugo sites feel app-like. Partial swaps, lazy content loading, modal systems, dynamic lists, and inline editing—all from static pre-rendered HTML.

Signature Approaches

01

Local-API Pattern

Hugo generates /api/*.json bundles that behave like API endpoints. Powers search engines, dashboards, and offline-first experiences.

02

Hugo as Data-Orchestrator

Import content from external sources at build time. CSV → JSON conversions, schema-driven automation, auto-generated documentation.

03

Faux Server Architecture

HTMX + Alpine.js mimics server logic client-side. User accounts via localStorage, condition-based rendering, static side effects.

04

Fragment-Driven UI

Hugo outputs html-fragments/, json-api/, and ui-components/. HTMX loads them on-demand, creating the illusion of an active backend.

Engineering Philosophy

Local-first, server-last — only use a backend when absolutely essential
Performance is UX — fast always beats complex
Static ≠ simple — a static site can behave like an application
Data belongs in structures, not in templates
HTML-first design — let HTML do the work
If Hugo doesn't support it… extend Hugo
